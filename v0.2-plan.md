# Implementation plan v0.2 — granulat pe sesiuni Claude Code

## Premise consolidate

- Video = textură (sprite cu frame-uri pre-extrase). **Zero audio din video.**
- Audio doar din track-uri externe declarate explicit de user.
- Frame extraction: pre-extract PNG sequence (opțiunea A).
- `end > trimRange` → freeze ultimul frame. `loop: true` opțional, suportat din start.
- Register asset video: warn pe rezoluție/durată mari, nu eroare.

## Reminder critic — dual schema

`apps/editor/app/types/commands.ts` ține tipurile UI separat de engine. **Orice câmp nou pe scenă (audio track, video item) trebuie adăugat în AMBELE locuri** sau e silent stripped. Toate sesiunile de schema/MCP au asta ca acceptance criterion explicit.

## Sesiunile

### S1 — Schema + types: audio tracks
**Scope:**
- Tip nou `AudioTrack` în engine schema JSON: `asset, start, end?, volume?, fadeIn?, fadeOut?`
- Adăugare în `apps/editor/app/types/commands.ts` (DUAL!)
- Validări: `start ≥ 0`, `end > start`, `volume ∈ [0, 2]`, `fadeIn/fadeOut ≥ 0`
- Composition JSON capătă secțiunea `audio: AudioTrack[]`

**Out:** MCP tools, ffmpeg, asset registration.
**Deliverable:** compoziții cu `audio[]` se parsează/validează; tipurile compilează în UI și engine.
**Verificare:** unit tests pe parser + 3 fixture JSON (valid, invalid duration, invalid volume).
**Estimat:** 3-4h.

---

### S2 — Asset registration extins pentru audio
**Scope:**
- `register_asset` acceptă `.mp3 .wav .aac .m4a .ogg`
- Integrare `ffprobe` → extrage `duration`, `sampleRate`, `channels`, `codec`
- Stocare metadata în asset registry
- `list_assets` întoarce metadata audio

**Out:** mux, MCP tools pentru tracks.
**Deliverable:** `register_asset` pe un mp3 returnează metadata; warning dacă lipsește ffprobe.
**Verificare:** test cu 2-3 fișiere audio reale (mp3, wav, m4a).
**Estimat:** 3h.

### S3 — MCP tools pentru audio tracks
**Scope:**
- `add_audio_track(asset, start, end?, volume?, fadeIn?, fadeOut?)`
- `update_audio_track(id, ...)`, `remove_audio_track(id)`, `list_audio_tracks()`
- Validări: asset există și e audio; durata track nu depășește durata compoziției (warning, nu eroare — aliniere cu Q6)
- Update doc MCP capabilities

**Out:** mux ffmpeg.
**Deliverable:** pot construi o compoziție cu 2-3 audio tracks via MCP.
**Verificare:** integration test parcurge add → update → list → remove.
**Estimat:** 3-4h.

---

### S4 — Audio mux pipeline post-render
**Scope:**
- Refactor render pipeline din 1 etapă → 2 etape:
  1. rawvideo → `temp_video.mp4` (fără audio, ca azi)
  2. mux: `temp_video.mp4` + N audio tracks → `output.mp4`
- Generator `filter_complex` pentru N tracks: `adelay`, `volume`, `afade` in/out, `amix`
- Resample forțat 48kHz pe toate sursele
- `-c:v copy` la mux (zero re-encode video)
- Cleanup `temp_video.mp4` după mux
- Flag `-movflags +faststart` opțional

**Out:** video items.
**Deliverable:** compoziție cu 1 voiceover + 1 music renderează corect; ffprobe pe output confirmă stream audio cu 48kHz.
**Verificare:** golden test — render fixture, ffprobe output, comparație waveform pe 3 puncte de timp.
**Estimat:** 5-6h.

**Checkpoint la final S4: audio muxing complet funcțional și shipable independent.** Poți pune un tag intermediar `v0.2.0-audio` aici dacă vrei să-l folosești înainte să termini video clips.

### S5 — Schema + types: video items
**Scope:**
- Tip nou `VideoItem` (extinde `SpriteItem` conceptual): `asset, x, y, width, height, anchor, start, end?, trimIn?, trimOut?, fit, loop`
- `fit ∈ {cover, contain, fill, none}` (default `contain`)
- DUAL update: engine + `apps/editor/app/types/commands.ts`
- Validări: `0 ≤ trimIn < trimOut ≤ asset.duration`, `end > start`
- **Explicit:** zero câmpuri audio pe `VideoItem`

**Out:** registration, extract, render.
**Deliverable:** compoziții cu video items se parsează; tipuri compilează în UI.
**Verificare:** unit tests parser + fixtures.
**Estimat:** 3h.

### S6 — Asset registration extins pentru video
**Scope:**
- `register_asset` acceptă `.mp4 .mov .webm .mkv`
- ffprobe → `duration, width, height, fps, hasAlpha, codec, pixelFormat`
- Warning policy:
  - rezoluție > 4K → warn
  - durată > 60s → warn
  - codec exotic (av1 cu hardware decode lipsă) → warn
- Metadata în registry, queryable

**Out:** pre-extract.
**Deliverable:** register video, warnings apar la limite, metadata corectă.
**Verificare:** test cu 4 video-uri (mic, 4K, lung, webm cu alpha).
**Estimat:** 3-4h.

---

### S7 — Pre-extract pipeline pentru video frames
**Scope:**
- Pre-render phase: pentru fiecare `VideoItem` distinct (asset+trimIn+trimOut+fps+resolution) → spawn ffmpeg:
  ```
  ffmpeg -ss <trimIn> -i <asset> -to <trimOut> -vf "fps=<compFps>,scale=<W>:<H>" cache/<hash>/%05d.png
  ```
- Cache cu hash determinist (asset path + mtime + params)
- Reuse între render-uri și între items care partajează aceleași params
- Progress events către caller
- Cleanup LRU pentru cache (configurabil, default 5GB)

**Out:** drawing la render time.
**Deliverable:** rulează render-ul → pre-extract apare în cache; al doilea render hit cache.
**Verificare:** test cu 1 video, două render-uri consecutive, al doilea trebuie să fie >5x mai rapid.
**Estimat:** 5-6h.

---

### S8 — Render-time drawing pentru video items
**Scope:**
- Renderer recunoaște `type: "video"`
- La frame `f`:
  - `localTime = compTime - item.start`
  - dacă `localTime > (trimOut - trimIn)`:
    - dacă `loop: true` → modulo
    - else → freeze la ultimul frame disponibil
  - `frameIdx = floor(localTime * fps) + 1`
  - `drawImage(cache/<hash>/<frameIdx>.png, ...)` cu transform `fit`
- Implementare `fit`: cover/contain/fill/none cu calcul dst rect
- Tweens existente (x, y, opacity, width, height) funcționează identic ca sprite

**Out:** MCP tools, parallelization.
**Deliverable:** golden render cu video + sprite + text e corect frame-by-frame.
**Verificare:** golden frame comparison la frame-uri cheie: t=0, t=mid, t=end-1, t=după-trim-cu-freeze, t=după-trim-cu-loop.
**Estimat:** 4-5h.

## Sesiuni opționale (decizie ta dacă rămân în v0.2 sau merg în v0.3)

### S11 (opt) — Cubic-bezier easing
Adaugă `cubic-bezier(x1, y1, x2, y2)` ca string în câmpul `easing` (în plus față de cele named). Solver Newton-Raphson sau De Casteljau. **2-3h.**

### S12 (opt) — Frame-range parallelization
Worker pool: split [0, N) frames în K range-uri, K procese paralele render → K segmente raw → concat. Beneficiu real pe video-uri ≥ 30s. **5-7h.**

Recomandare: dacă vrei v0.2 livrabil rapid, **amână S11+S12 la v0.3**. Audio + video aduc deja valoare imensă singure.
