01 — TL;DR

What davidup is, who it's for, and where v1.0 lands.

single paragraph, no euphemisms

One engine. Three surfaces. Sharp v1.0 scope.

davidup is a ~7.2k LOC TypeScript core (schema, resolver, renderer, drivers), an AdonisJS + Inertia + Vue editor that funnels every mutation through a single command bus, and a stdio MCP server that lets AI agents drive both. v1.0 is a local-first, single-user product — production-quality at that scope, deliberately not SaaS-ready yet.

Verdict — v1.0
Ship the local-first app today. The SaaS shell is real but bounded engineering — 3 weeks to alpha, 3–5 months to public.

Engine, editor, and MCP are tight, tested, and consistent inside a single process. The validate-then-crash gaps are 3 × one-day fixes. The path from "local tool" to "hosted SaaS" is mostly the projectStore-to-per-tenant refactor and a few hours of auth wiring. Don't platformify ahead of the user signal.

03 — architecture

Three deployable surfaces, one canonical state.

layers

Engine, editor, MCP — pure ↑ at every layer.

The engine never imports from compose, compose never imports from drivers, drivers import from both. The editor's MCP bridge intercepts every mutating MCP tool and routes it through the same CommandBus the UI uses — that's what makes human ⇄ agent edits byte-equal.

Critical seam: apps/editor/app/services/mcp_bridge.ts routes every mutating MCP call through the same commandBus.apply() the HTTP UI uses. Read-only tools run against per-call hydrated stores.

04 — getting started

Install once; three "hello worlds".

install

One bun install, three entry points.

A · browser preview

bun run dev:browser opens examples/browser-demo on Vite. The page imports attach from davidup/browser, calls attach(comp, canvas), and the RAF loop starts.

B · render to MP4

bun run examples/render.ts. One Canvas reused across every frame, RGBA piped into ffmpeg's stdin with backpressure. ffmpeg stderr tail surfaces in any thrown Error.message.

C · drive it with an agent

Wire davidup-mcp into your client. Standalone: bun run src/mcp/bin.ts. Editor-hosted: launch davidup edit with DAVIDUP_MCP_STDIO=1.

// minimal MP4 render
import { renderToFile } from "davidup/node";
import { validate } from "davidup/schema";
if (!validate(comp).valid) throw new Error("invalid");
await renderToFile(comp, "out.mp4", { codec: "libx264", crf: 18 });

05 — the editor

Five regions, one canonical composition.

daily workflows

Edit anywhere, save nowhere.

Boot with davidup edit <project-dir>. The CLI spawns AdonisJS with DAVIDUP_PROJECT set, polls until reachable, and opens the browser. Every mutation — Inspector input, Timeline drag, Library drop, MCP agent — routes through POST /api/command and lands as one Zod-validated Command on the CommandBus, which serializes via a microtask queue, applies to a freshly-hydrated engine store, validates, and persists via a 500ms debounced atomic disk write.

06 — authoring

Items, layers, tweens, behaviors, templates, scenes.

composition

Atomic primitives → composable units.

Items are sprite, text, shape (rect / circle / polygon), group. Every item has a transform: x, y, scaleX, scaleY, rotation, anchorX, anchorY, opacity. Layers carry positive z with stable-sort by declaration order as the tiebreaker. Tweens animate a single property from from to to over [start, start+duration]; the engine bucket-indexes them by (target, property) and binary-walks at sample time — no per-frame sort.

The 11 built-in behaviors

apply_behavior is atomic: if any emitted tween conflicts with an existing one, the entire expansion is rolled back.

fadeIn fadeOut popIn popOut slideIn slideOut rotateSpin kenburns shake colorCycle pulse

The 5 built-in templates

titleCard lowerThird captionBurst bulletList kenburnsImage

User templates: define_user_template { id, description?, params?, items, tweens? }. Any $behavior block inside a template's tweens is expanded before being committed.

Scenes and time-mapping

Scenes are sealed mini-compositions with their own duration, items, tweens, params, and assets. The instance is expanded to a synthetic group + namespaced inner items + time-shifted tweens. Four time-mapping modes on add_scene_instance / update_scene_instance:

ModeShapeEffect
identity{ }Baseline, the default.
clip{ fromTime, toTime }Trim a sub-range of the scene's timeline.
loop{ count ≥ 1 }Repeat back-to-back. Iteration math uses parentStart + i * sceneDuration — non-cumulative rounding.
timeScale{ scale }Divide every tween's start / duration by scale.

End-to-end demo: examples/time-mapping-mcp/ exercises all four modes via in-process MCP dispatch.

07 — assets

Hash-deduped, two-root, watched.

library

Upload, dedupe, register, drag.

Drop one or more files onto the Library panel or anywhere on the editor; the page shows a drop veil while a drag is active. POST /api/assets multipart triggers the pipeline:

  1. Reject non-supported extensions (png/jpg/jpeg/webp/gif/svg/mp4/mov/webm/mkv/mp3/wav/ogg/m4a/aac/flac); size cap 50 MB. D6 font extensions are missing from the controller list even though the pipeline supports them.
  2. SHA-256 hash the bytes → name file <hash><ext>.
  3. ffprobe / loadImage for metadata; generate a thumbnail when applicable.
  4. Register in the destination library's index.json (project or global). Atomic tmp + rename.

Hash dedup means re-uploading the same bytes is a no-op.

Two roots

project pool <project>/library/ — per-project, swapped on project load.
global pool ~/.davidup/library/ — per OS user, attached once at boot. Override via $DAVIDUP_LIBRARY.

Project wins over global on (kind, id) collisions; the loser carries overridden: true. Watcher coalesces events with a 100ms debounce; UI polls every 2s for cross-tab changes.

MCP equivalents

  • register_asset { id, type, src, family? } — fonts require family.
  • list_assets { compositionId? } — declaration order.
  • remove_asset { id } — errors E_ASSET_IN_USE if referenced. Idiomatic swap: register_asset with the same id over a new src.
  • list_library { q?, kind?, scope? } — editor-only.

08 — rendering

UI flow, MCP flow, history.

render

Same input, same pixels, every host.

From the editor

POST /api/renders { filename? } → RenderJob constructed with the current snapshot of projectStore.composition → fire-and-forget job.run() → response with { jobId, totalFrames, outputPath, relativeOutputPath, eventsUrl }. Output lands in <project>/renders/.

Browser subscribes to GET /api/renders/:id/events (SSE). Late subscribers replay the terminal state.

EventPayload
progress{ jobId, frame, total, elapsedMs }
done{ jobId, outputPath, relativeOutputPath, frameCount, durationMs }
error{ jobId, message }

One render at a time per UI (single-slot). The server registry can hold 32 jobs. RenderHistory.vue lists past renders; macOS-only row actions: Reveal (Finder), Play (QuickTime). D5 the prefix-check is case-sensitive on HFS+. Non-macOS gets 501 on the shell endpoint. polish no Linux/Windows reveal parity.

From MCP

  • render_preview_frame { time, format? } → { image (base64), mimeType, width, height }. Validates first.
  • render_thumbnail_strip { count, format? } → N uniformly-sampled frames + sample times.
  • render_to_video { outputPath, codec?, crf?, preset?, pixFmt?, wait? } — standalone blocks; editor-hosted is async by default. M2 returns three different shapes across hosts.
  • get_render { jobId } — editor-only snapshot.
  • list_renders {} — editor-only; newest first.

ffmpeg options: codec libx264 (default) or libx265; crf integer 0–63 (default 18); preset; pixFmt. polish the editor UI exposes only filename; codec/CRF/preset are MCP-only.

40+ atomic tools, one canonical state.

agent surface

Atomic. Orthogonal. Structured errors.

Wiring

Two server entrypoints. The standalone bin src/mcp/bin.ts ships with no project / library / render queue — useful for one-off agent flows. Error envelope

MCPErrorBody carries code, message, optional hint, plus issues / warnings arrays and a details bag. 26 stable codes. Agents branch on code, not on substring matching.

Idempotency

Every add_* / register_asset accepts an optional id. Always supply one — retried calls return E_DUPLICATE_ID instead of silently duplicating, and transcripts replay deterministically.

Worked example — 10-second Acme Coffee ad

create_composition { width: 1280, height: 720, fps: 60,
                    duration: 10, background: "#0a0e27" }
add_layer { id: "bg", z: 0 }
add_layer { id: "fg", z: 10 }
register_asset { id: "logo", type: "image", src: "./assets/logo.png" }
apply_template { templateId: "titleCard", layerId: "fg",
                 params: { title: "Acme Coffee", subtitle: "Wake up." } }
add_sprite { layerId: "bg", asset: "logo", x: 640, y: 360,
             width: 400, height: 400, opacity: 0 }
apply_behavior { target: "<sprite-id>", behavior: "fadeIn",
                 start: 0, duration: 1.5 }
apply_behavior { target: "<sprite-id>", behavior: "kenburns",
                 start: 1.5, duration: 7 }
validate {}
render_preview_frame { time: 5 }
render_thumbnail_strip { count: 6 }
render_to_video { outputPath: "/abs/path/acme.mp4",
                  codec: "libx264", crf: 18 }

The agent gets six base64 PNGs back, looks at them, decides what's wrong (cropped text, mistimed pop, wrong color), patches, re-previews, then commits. This iteration loop — preview-frame-as-base64 + deterministic engine — is what makes davidup work for agents.

10 — determinism

What's guaranteed, what isn't.

honest contract

Bit-exact resolved state. Host-bounded pixels.

Guaranteed within a single host

No PRNG anywhere in src/. No Date.now() in the resolver or renderer. Node render time is i / fps, not the wall clock. Stable-sorted iteration in every compose pass. OVERLAP_EPS = 1e-6 documented inline with a regression test.

Bounded across hosts

Pixels differ between browser Canvas2D and Node skia-canvas — they must: font hinting, sub-pixel AA, image decoders, and bezier rasterizers are all implementation-defined. The product positioning ("MP4 is ground truth, browser is preview") makes the trade acceptable.

Three validation gaps that allow "validate-then-crash"

  • E1 LayerSchema.blendMode is z.string() — any value validates, then different hosts handle the invalid string differently.
  • E4 Color-tween endpoints aren't validated for parseability; lerpColorString throws at render time on "magenta".
  • E6 clampForProperty only clamps transform.opacity — overshoot easings can drive width / height / fontSize negative, crashing some hosts on arc(r, r, -5, ...).

Three one-day fixes close the entire failure class.

13 — SaaS readiness

The honest scorecard, the security findings, the keystone move.

scorecard

Local-first, by design. SaaS-shell is unstarted.

The vision doc and PRD both explicitly defer multi-tenant SaaS to v2.0. The code honors that scope honestly — it does not pretend to be SaaS-ready, and it does not hide its single-user assumptions.

DimensionStarsOne-line verdict
Tenancy model0/5No tenant concept exists in code. Single-process, single-project, OS-user level.
Authentication1/5Adonis auth scaffolded. Zero login/register/logout routes; zero auth middleware on any route.
Authorization0/5No ownership check anywhere.
Asset storage2/5Hash-named, idempotent, ext + size validated. No MIME magic, no decompression-bomb cap, no AV, no S3, no per-tenant prefix.
Render pipeline1/5In-process, no queue, no concurrency limit, no per-tenant fairness, no meter, no timeout, no cancel after start.
MCP exposure1/5Stdio only, runs as the OS user. No auth, no rate limit, no scope.
Observability1/5Pino logs to stdout. No metrics, traces, Sentry, audit table, or request-id correlation.
Security headers2.5/5XFO=DENY, HSTS, CSRF on session routes — but CSP disabled and /api/* exempt from CSRF.
Compliance / legal1/5No ToS, privacy policy, DPA, data-export, delete-me, or font-licensing story.
Deployment1/5No Dockerfile, no CI workflow, APP_KEY committed, skia-canvas container build untested.

Aggregate readiness for hosted multi-tenant: ~10%.

keystone move
Refactor project_store.ts and every importer of it into a tenant-aware façade — before adding auth, billing, or Dockerfile.

Every other SaaS-ification item is a brick that needs this in place. Once the store knows about tenants, auth becomes trivial and quotas become "one row in tenant_usage_daily". The risk inside the refactor is the singleton coupling that has metastasized across the command bus, MCP bridge, render worker, and library index — each coupling is a place a tenant could leak into another's state if the refactor is incomplete.

14 — roadmap

From "ships locally" to "bills 1000 tenants".

Private alpha — 5 to 10 tenants, ~3 weeks one engineer

01 · auth

Login + apply

Magic-link /login, /register, /logout. Apply auth middleware to every /api/* route. 1.5d.

02 · tenancy

Project model

Project table with owner_user_id. Refactor projectStore to per-(user+project) cache. Tenant-scope ~/.davidup/. 4d.

03 · hard fixes

Auth keys + SSRF

Rotate APP_KEY. SSRF fix on asset.src. Re-enable CSRF on /api/* or switch to bearer tokens. 2d.

04 · render safety

Cap + timeout

pLimit(2) per process. RENDER_TIMEOUT_MS default 10min. 503 when full. AbortSignal plumbed into renderToFile. 1d.

05 · uploads

Magic + quota

file-type magic-byte sniff. Reject decoded images > 64 megapixels. Per-tenant disk quota. 1.5d.

06 · metering

Stripe

usage_events table. Writers in render worker + asset pipeline + MCP router. Stripe Meter wiring. 3d.

07 · ops

Sentry + Docker

Sentry hook. Request-id middleware. Privacy / ToS pages. Dockerfile. Hetzner CX32 + Coolify. Health alert. 2d.

08 · ship

Friends-and-family

Smoke-test runbook. Invite 5 — 10 trusted users. Watch metrics. Iterate on their behavior, not on this audit.

Public launch — 1000+ tenants, ~3–5 months

P1 · split

Web ↔ worker

BullMQ + Redis. editor-web publishes jobs, render-worker pops them. SSE proxied via Redis pub/sub.

P2 · storage

R2 / S3

BlobStore interface across asset pipeline, composition writer, render writer. Presigned download URLs.

P3 · DB

Postgres

SQLite → Postgres. Per-tenant connection pooling. Library index migrates from per-project library/index.json + fs.watch to DB rows.

P4 · hosted MCP

HTTP+SSE per tenant

Move MCP from stdio to HTTP-SSE transport with bearer-token auth. The keystone differentiator for the agent-native platform pitch.

P5 · abuse

Limiter + WAF

@adonisjs/limiter on every mutating endpoint. Per-tenant render-minutes guardrails. Cloudflare WAF.

P6 · compliance

GDPR + C2PA

Data-export, delete-me, DMCA takedown form. C2PA provenance baked into rendered MP4s. AV scan on uploads.

P7 · observability

Loki + Tempo

Pino → Loki, OpenTelemetry → Tempo, Prometheus → Grafana. Per-tenant dashboards. Render-queue depth, p95 latency, MCP error rate, per-tenant storage.

P8 · hardening

CSP, HSTS, SOC2 primitives

CSP enforced. HSTS preload. HTTP/3 termination. Change log, access log, secrets rotation. Not SOC2-certified, but SOC2-ready.

15 — verdict for v1.0

One notch above "ships."

The engine, the editor server, the MCP bridge, and the precompile pipeline are deliberate, tested, internally consistent code. The author knew they were building a single-user local tool and did so cleanly. Three one-day fixes (blend-mode enum, color-tween parseability, numeric-property clamping) close the "validate-then-crash" failure class and meaningfully sharpen the determinism story.

The MCP layer is the strongest part of the project. Atomic, orthogonal, structured-error tools backed by a deterministic engine, with an editor bridge that proves human + agent edits can share one canonical state. What gates v1.0 quality here is consistency, discoverability, and SaaS-readiness — all bounded, all mechanical.

The editor is shippable as a v1.0 local-first single-user app and meaningfully impressive at that scale. Visible bugs are minor; none are corruption-class under the documented single-user workflow. Top polish items: undo shortcut, Stage drag, render presets UI, Linux/Windows reveal parity.

final word
Ship v1.0 as a local-first tool. Refactor the project store next. Don't platformify ahead of the user signal.

The dominant risk for this project right now is premature platformification. The engine is good. The editor is good. The hard part is converting that quality into per-user value at a price someone will pay — and the SaaS shell needed to do that is much smaller than the vision document hints at. Build the alpha shell. Ship to ten paying users. Let their behavior pick the next ten items, not this audit.

Same input, same pixels, every host.
