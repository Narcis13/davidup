## Bugs

| # | Pri | Bug | Repro | Cause |
|---|---|---|---|---|
| **B-5** | P1 | `davidup render` breaks every `global:` (and `bundled:`) asset src | a comp with `{ "type": "font", "src": "global:fonts/anton-400.woff2" }` → `No such file or directory … /<comp dir>/global:fonts/anton-400.woff2` | `resolveAssetSources` (`src/cli/render.ts:~100`) resolves any non-absolute src against the comp dir, before `resolveGlobalSrc` (`src/assets/node.ts:176`) ever sees the prefix. The same copy lives in `apps/editor/app/workers/render_worker.ts:74-88`, so editor exports of a comp using a global-library asset should fail the same way (*unverified in the editor*). |
| **B-6** | P1 | A video item without `fit` crashes the render | hand-written `{ "type": "video", …, "start": 0 }` (no `fit`) → `undefined is not an object (evaluating 'r.sw')` from both the CLI and `renderToFile` | `fit` has a Zod `.default("contain")` (`src/schema/zod.ts` `VideoItemSchema`), but `precompile` + `validateComposition` never apply parse defaults, and `drawVideo` (`src/engine/render.ts:434`) passes `item.fit` straight to `computeFitRects`, which returns `undefined` for an unknown mode. `loop` has the same `.default(false)` shape (harmless today). MCP `add_video` always writes `fit`, which hides it. |
| **B-7** | P2 | VP9 `.webm` alpha is lost when the clip is used as a video item | render an overlay with `--codec libvpx-vp9` (alpha is in the file), use it as a `video` item over a blue bg → transparent areas come back **black**. ProRes 4444 `.mov` round-trips correctly. | `buildExtractArgs` (`src/drivers/node/videoExtract.ts:350-374`) lets ffmpeg pick the native `vp9` decoder, which ignores the alpha side-channel; it needs `-c:v libvpx-vp9` *before* `-i` when the asset is VP9 with `hasAlpha`, and `-pix_fmt rgba` on the PNG output to be explicit. So davidup can export alpha webm but can't consume its own output. |
| **B-9** | P1 | `audioMaster.targetLufs` + a ranged render fails the mux | a comp with one WAV track (`boom.wav`, start 24) and `audioMaster: { targetLufs: -14, limiter: false }`, `--from 24 --to 30` → `Cannot select channel layout for the link between filters Parsed_aresample_6 and Parsed_apad_7 … Error reinitializing filters!` Deterministic, and it fails through the API too. The same comp without `targetLufs` renders. | The pass-2 bus (`buildAudioFilterComplex`, `src/drivers/node/audioMux.ts:206-225`) is `loudnorm(linear) → aresample=48000 → [alimiter] → apad`. When ffmpeg re-initialises the graph mid-stream, loudnorm's output has no pinned layout and negotiation fails. **Verified fix:** append `aformat=channel_layouts=stereo` right after that `aresample` (the hand-edited graph renders). Also add a regression test with a track that starts exactly at `range.from`. The showcase drops `targetLufs` until this lands. |
| **B-8** | P2 | 13 of 14 seed-library templates place text in point mode with centre coords | `ctaButton` label sits visibly above the pill's centre (its baseline is on the centre) | Seeded before text v2 (`scripts/seed-global-library.ts`): text uses `anchorX/Y: 0` + `align: center` with `x/y` = the intended centre. Since S13, anchor 0.5/0.5 (box mode) centres on the measured block. Affected: `compareSplit`, `countdown321`, `ctaButton`, `endCard`, `quoteCard`, `sectionDivider`, `statBig`, `subtitleBar`, `tagPill` (`logoBadge`/`progressBar` have no text). Since G4 the showcase names `global:ctaButton` directly and can no longer patch it, so its Follow label sits high and the 𝕏 mark is offset to clear it — undo that nudge here. |

## Limitations that cost the most authoring effort

| # | Limitation | What it forced in the showcase |
|---|---|---|
| **L-1** | A composition can't reference global-library **templates or behaviors** by id; `precompile` sees only `templates{}`, built-ins and the process registry. There is no composition-scoped `behaviors{}` block, so an executable user behavior only works inside an MCP/editor session. | `build.mjs` read `~/.davidup/library/templates/ctaButton.template.json` and inlined it; `render.ts` called `registerBehavior()` before compiling. **Fixed in G4** — the showcase names `global:ctaButton` and carries `neonFlicker` in its own `behaviors{}` block, and `davidup render` renders the film. |
| **L-2** | A root **scene instance can't be owned by a group** (`E_INVALID_VALUE: Scene instance "orr0" has no layerId and is not referenced by any layer`). The v1.2 ownership fix covers groups *inside* scene definitions only. | Each orrery pops in by tweening x/y alongside scale (`x = cx − 150·s`, same easing) instead of scaling a wrapper group. |
| **L-3** | **Groups and scene instances ignore `anchorX/Y`** (no intrinsic box, `render.ts:318-331`, `:724`). Scaling/rotating "about the centre" needs the children laid out around (0,0) or the x/y compensation above. | Same as L-2; every group in the file is authored centre-origin. A scene's declared `size` could serve as its anchor box. |
| **L-4** | The expression language has only `+ − * / %`, `min`, `max`, `round`. No `sin`/`cos`/`sqrt`/`abs`/`floor`/`clamp`/`pi`. | The 960-dot iris is laid out in polar form by giving each dot a `rotation` and tweening a large negative `anchorX` (pushes it out along its own angle). `floor(x)` has to be spelled `round(x − 0.5)`. |
| **L-5** | No gradient fills (linear/radial) on shapes or text. | The ambient background is three 1000 px circles under a 140 px blur in an isolated group, the most expensive thing in every frame (see P-1). |
| **L-6** | Per-frame text (frame counter) is still N items (900) + windows. Already deferred in `v1.2_fixes_plan.md` as a render-time token. | 900-entry `$repeat` (works fine since F3). |

## Performance

| # | Finding |
|---|---|
| **P-1** | Measured on an M-series Mac: the final 900 frames took **617 s (1.46 fps average)**, and each 180-frame Droste pass (the reveal: a full-frame video in an isolated group with a `shadow` effect, plus the always-on 140 px aurora blur) took about 120 s (1.5 fps). So speed is low throughout the film, not only in the reveal, which points at the always-on blurred aurora (not measured in isolation yet; profile first). Each isolated/effected group allocates a full-canvas offscreen and blurs it at full resolution every frame. Ideas: (a) size offscreens to the group's transformed bounds, not the canvas; (b) blur large σ on a downscaled surface (σ ≥ 20 → ½ or ¼ res, then upscale; visually identical); (c) cache the offscreen when no descendant has an active tween at `t` (static groups). Numbers are in `examples/showcase-vertical/output/render.log`. |
| **P-2** | `render.ts --stills` compiles the whole composition once per still (≈0.5 s each). The MCP `render_preview_frame` path probably does the same per call. A compile cache keyed on the source hash would make still-scrubbing near-instant. *(unverified for MCP)* |

| **P-3** | With the limiter only (B-9 forced dropping `targetLufs`), the showcase measures **−8.9 LUFS integrated, +0.4 dBFS true peak** after AAC encoding. `alimiter` is sample-peak, not true-peak, so AAC inter-sample overs exceed the ceiling. Consider a true-peak-aware ceiling (oversampled limiter, or lower the default ceiling to −1.5 dBTP when no `targetLufs` is set). |

## Minor / DX

- `renderToFile(comp, "<dir>")` without `format: "png-sequence"` fails with ffmpeg's `Unable to find a suitable output format for '<dir>'`. Detect an existing directory and either switch to PNG output or throw a clear `E_OUTPUT_PATH`.
- `W_TWEEN_TRUNCATED` is emitted once per tween. A `$repeat` that overruns reports N copies. Group by the `$repeat` source when the source map has one.
- Environment, not davidup: Homebrew's `/opt/homebrew/bin/ffprobe` (ffmpeg 8) is broken on this Mac (missing `libx265.215.dylib`), while `ffmpeg` on PATH is 6.0. davidup uses `ffprobe-static`, so renders are unaffected. `brew reinstall ffmpeg` fixes the shell.

Tests: a CLI render of a comp with a `global:` image + font (point `DAVIDUP_LIBRARY` at a fixture dir) and an editor render-worker unit test.
**Verify:** baseline + `davidup render` on `examples/showcase-vertical/composition.json` gets past asset loading (the user behavior still needs G4).

### Session G2 — Apply schema defaults before render (B-6)
**Files:** `src/compose/precompile.ts` (end of pipeline), `src/schema/zod.ts` (`VideoItemSchema` defaults), `src/engine/render.ts:434`.
**Steps:** decide on one of two options. (a) `precompile` returns the Zod-parsed composition, which fills every `.default()`; check that strict-schema errors and source maps survive. (b) Keep the raw shape but make every reader default-safe (`item.fit ?? "contain"`, `item.loop ?? false`). Pick (a) if it is byte-stable on the goldens, since it closes the whole class. Test: a hand-written video item without `fit`/`loop` renders a letterboxed frame.
**Verify:** baseline + goldens unchanged.
**Commit:** `fix: schema defaults reach the renderer — video items without fit no longer crash (B-6)`
**Decided:** neither (a) nor (b) verbatim — `precompile` ends with a new `applySchemaDefaults` pass
(`src/schema/defaults.ts`) that fills the declared `.default()`s *in place*, reading them out of `ItemSchema` so the
pass can't drift (a test walks the schema tree and fails if a default lands where the pass doesn't look). Returning
`parsed.data` was rejected because a strict parse drops `$…` / `x-…` extension keys, and `precompile`'s output is
written back over the user's `composition.json` by the editor and stored by MCP `replace_composition`; it also has to
stay total for invalid input so `validate` can report E_SCHEMA. `drawVideo` additionally falls back to `contain` for
direct engine callers. Goldens byte-identical.

### Session G3 — Consume VP9 alpha (B-7)
**Files:** `src/drivers/node/videoExtract.ts:350-374` (`buildExtractArgs`), the `VideoExtractSpec` (needs codec + hasAlpha from the asset), extraction cache hash (bump `VIDEO_EXTRACTION_VERSION`).
**Steps:** when the asset's `codec` is `vp9` (or `vp8`) and `hasAlpha`, emit `-c:v libvpx-vp9` / `libvpx` before `-i`. Always add `-pix_fmt rgba` for PNG output. If `hasAlpha` is unknown (asset not probed), probe `alpha_mode` tag. Test: render a transparent comp to `.webm`, use it as a video item over a solid bg, pixel-probe a transparent corner = the bg colour (mirror the existing ProRes test).
**Verify:** baseline + the new round-trip test.
**Commit:** `fix: VP9 alpha survives frame extraction (B-7)`
**Decided:** `-pix_fmt rgba` is applied *only* when the source carries alpha, not always — forcing RGBA on opaque
sources moves swscale's rounding by up to 3/255 and shifted the three `video-*` goldens for no benefit. The decoder
override is the load-bearing half (verified by disabling each half against the new round-trip test); the explicit
`-pix_fmt` on alpha specs only states what ffmpeg already negotiates from yuva frames. `VideoExtractSpec` gained
`alpha` + `decoder`, both hashed, and `VIDEO_EXTRACTION_VERSION` is 3. `hasAlpha`/`codec` come from the asset;
a `.webm`/`.mkv` asset missing them is probed by a new best-effort `probeVideoSync` (memoised on path+mtime+size so
the three callers that recompute a spec hash agree). Other containers are never probed — their alpha is in the pixel
format, which any decoder honours.

### Session G4 — Library templates/behaviors from a composition (L-1)
**Files:** `src/compose/precompile.ts`, `src/compose/templates.ts`, `src/compose/behaviors.ts`, `src/schema/zod.ts` (top-level `behaviors`), dual schema, README.
**Steps:** (1) composition-scoped `behaviors: { name: descriptor }` registered for the duration of one compile (not into the global overlay), so a comp that defines and uses an executable behavior renders from the CLI. (2) `$template: "global:ctaButton"` / `$behavior: "global:neonFlicker"` resolved from the library root at precompile (Node only; browser gets a clear `E_FEATURE_UNAVAILABLE`). Alternatively make `$ref` accept `global:` paths, which is smaller and composes with (1). Delete the inlining + `registerBehavior` workaround in `examples/showcase-vertical/`.
**Verify:** baseline + `davidup render examples/showcase-vertical/composition.json` works end to end (needs G1).
**Commit:** `feat: composition-scoped behaviors; global: templates/behaviors resolve at compile (L-1)`
**Decided:** both halves, and `$ref` was *not* taught `global:`. (1) `expandBehaviors` reads a top-level
`behaviors{}` and registers it for that one compile (never the process registry), stripping the key like
`templates` / `scenes`; lookup order is composition block → `options.behaviors` (MCP session) → registry →
built-ins. (2) A new pass `resolveLibraryRefs` (`src/compose/libraryRefs.ts`) runs in `precompile` between `$ref`
inlining and the expansion passes: it walks for `global:`-prefixed `$template` / `$behavior`, loads
`<root>/templates/<id>.template.json` / `<root>/behaviors/<id>.behavior.json` transitively, and merges them into
the composition's own compile-time blocks *under the prefixed key* — so no expansion pass learns about the
library and an authored `"global:<id>"` key shadows the file. `$ref` was left alone: it inlines a JSON *value* at
a path, while a library reference is a named definition that also has to work from inside a template body, where
there is no place to hang a `$ref`. Node only (lazy `node:path` + `defaultGlobalLibraryRoot`, so browser bundles
stay clean); a non-Node runtime gets `E_FEATURE_UNAVAILABLE`. No dual-schema change: `behaviors` is a
composition-file block, not an MCP command shape, and `commands.ts` mirrors no authoring block (`templates` /
`scenes` are absent from it too); `CompositionSchema` is likewise unchanged, since it validates the *canonical*
output the pass strips these from. The showcase's `ctaButton` copy and `registerBehavior` call are gone; its
B-8 label patch went with them, so the Follow label sits on the library's point-mode baseline (the 𝕏 mark moved
to clear it) until G5 re-seeds the library.

### Session G7 — Expression functions (L-4)
**Files:** `src/compose/params.ts:321-333, 515-521`, `REPEAT_EXPRESSIONS_DESIGN.md`, `tests/compose/params.test.ts`.
**Steps:** add `sin cos tan atan2 sqrt pow abs floor ceil clamp(x,a,b) lerp(a,b,t)` and the constant `pi`. All are pure IEEE math, so determinism holds, but note that `Math.sin` is not guaranteed bit-identical across JS engines. Round results to 1e-9 before use in positions, or document the node↔browser tolerance. Rewrite the showcase iris with `x: "${cos(...) * r}"` if it reads better.
**Verify:** baseline + tests per function + an error test for arity.
**Commit:** `feat: trig / sqrt / floor / clamp in template expressions`
