01 — Route target

Decide where "back" actually goes.

decision · navigation

"Back to projects" points at /, not /editor.

The "projects" surface in this app is the project picker at the root route — apps/editor/start/routes.ts:21 wires / to HomeController.show, which renders pages/home.vue (the open-existing + create-new + recents UI). /editor is the editing canvas for an already-loaded project, which isn't the projects list.

Verdict

Both error pages use <Link href="/">.

The picker IS the projects list. Sending users to /editor would land them on whichever project happens to be loaded — or nothing useful — which doesn't match the wording.

02 — Link choice

Inertia <Link> vs. a plain anchor.

decision · framework

Use Inertia's <Link> over a raw anchor.

Imported Link from @inertiajs/vue3 for the CTA on both pages. Consistent with home.vue's navigation idiom (router.visit('/editor')) and avoids a full page reload when the error is reached mid-app. Genuine server 404s hit as a fresh request anyway, so <Link> doesn't break that path — it just smooths the in-app case. 

// pages/errors/not_found.vue (excerpt)
import { Head, Link } from '@inertiajs/vue3'

<Link href="/" class="btn btn-primary">Back to projects</Link>

03 — Visual source

Where the tokens come from.

decision · styling

Tokens copied from home.vue, not lifted from a shared module.

Both error pages reuse home.vue's palette inline — background radial, #0a0a0a base, #5b7cfa accent, 'Instrument Sans' + 'JetBrains Mono' pair, the 12px uppercase brand chip. There is no shared design-token module in inertia/css/ worth importing; home.vue itself uses <style scoped> with literal values.

04 — 404 vs 500

Same skeleton, different accent.

design · variant

Color is the only thing that differs.

Both pages share the skeleton: brand chip → giant numeric code → title → sub → CTA. The 404 keeps the blue accent on its digits; the 500 swaps to the red error tone and adds a monospace <pre> showing error.message. Color is the cheapest cue between "missing route" and "server blew up."

Acceptance · Same vertical rhythm; only the digit gradient and the optional <pre> distinguish the two surfaces.

05 — Fallback

Don't print undefined.

defensive · server_error.vue

Fall back when error.message is missing or blank.

The previous server_error.vue rendered {{ error.message }} directly, which prints undefined if the Inertia handler ever passes an object without message. A computed normalises to a generic line when missing or blank — defensive against a thrown non-Error value (e.g. a string throw) or a production build that strips the message. Cheap; prevents a bare undefined in the UI. 

// pages/errors/server_error.vue (excerpt)
const message = computed<string>(() => {
  const raw = props.error?.message
  if (typeof raw === 'string' && raw.trim().length > 0) return raw
  return 'Something went wrong on the server.'
})
